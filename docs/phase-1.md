# Phase 1: Python simulation skeleton

The simulation is a headless Python package. `SoccerSimulation.step(dt)` calls decision making, action application, physics, and rule resolution in that order, then returns `state`. The engine currently uses `initialize_rondo(config)` for a 3v1 scenario; `initialize_game(config)` still supplies the original 3v3 state. A defender presses the carrier directly when the ball is controlled, predicts an interception when it is loose and moving, and chases its position when stationary. Within 1 m, players become receivers; contact establishes control. Carriers hold position for the rondo and, under pressure within 3 m, try teammates from nearest to farthest until a clear passing lane is found. If every lane is blocked, the carrier holds. Pass speed compensates for distance and rolling friction to predict at least 3 m/s at the reception point. Simultaneous claims and opponent challenges use random contests, with an optional seed for repeatability. Physics includes arrival, braking, turning limits, rolling friction, disc contacts, and optional ball containment. Match rules remain future work. See [physics.md](physics.md) for the model and evidence.

The Python visualizer opens a Pygame window and draws a plain-data copy of the current state after each step. It can pause, single step, reset, and drag the ball. The React frontend lives under `frontend/` and renders a separate, static sample using Canvas. There is no API, shared runtime, or import between Python and TypeScript.

The next useful step is to add one defensive job or ball interaction at a time, with a scenario test for each. When the simulation produces meaningful states, choose a transport such as saved JSON traces or a local API, then feed those states into the existing Canvas renderer.
