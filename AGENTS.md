# Development log

When changing simulation logic, tactics, physics, scenario setup, or behavioral parameters, append a concise dated entry to `docs/development-log.md` in the same task. Include what changed, why, important parameters/formulas, and verification actually performed. State when verification was not run.

Preserve earlier entries so experiments remain traceable. Distinguish implemented behavior, observations, and proposed work; do not invent dates, measurements, or passing test results. Documentation-only housekeeping does not need its own log entry.
